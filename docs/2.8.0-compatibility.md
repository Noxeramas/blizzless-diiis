# Running DiIiS with the 2.8.0 client

DiIiS was written for client 2.7.4.84161. This fork runs the current Battle.net client, 2.8.0.99920, and reads
game data from the player's own installation. This page lists what differs between the two versions, what has
been fixed, and what is still open. The tools that produced it are in [`tools/protocol`](../tools/protocol/README.md).

## How it was checked

| Area | Method |
|---|---|
| Network messages | Field layouts read from the running 2.8.0 client, compared with DiIiS's `Encode`/`Parse` methods. |
| Attributes | Ids and value encodings from the client's attribute table, compared with `GameAttribute.List.cs`. |
| Game data | 150 files per data type from the bundled 2.7.4 MPQs and the 2.8.0 install, compared byte by byte. |
| Message handling | Opcodes the client sends (from its message dispatcher), compared with the handlers in DiIiS. |

## Differences between 2.7.4 and 2.8.0

### Battle.net

| Difference | Status |
|---|---|
| Game requests go through a new service, `bnet.protocol.game_utilities.v2.client.GameUtilities`. | Fixed: `GameUtilitiesServiceV2` forwards to the 2.7.4 handlers. |
| The login SDK dropped `OnGameAccountSelected` (AuthenticationListener method 14). | Harmless: the client logs `invalid_method_type` and continues. |

### Game messages

| Difference | Status |
|---|---|
| Hero state has a new 32-bit field after the played flags (hero list, `NewPlayerMessage`). | Fixed |
| Loadout items, trickle, synced game data, saved conversations and saved quest updates encoded differently. | Fixed |
| The map takes its act from the last waypoint's level area (opcode 61); the client crashes if it was never sent. | Fixed: sent on join and after each waypoint teleport. |
| `PlayerLoadoutDataMessage` has 4 legendary power slots, not 5. | Fixed (the server doesn't send it yet). |
| Opcodes 554, 555 and 557–559 are new server-to-client messages. | Not used yet; probably newer season features. |
| `DynamicQuestObjectiveMessage` needs an SNO name. | Open |

Every other message the comparison could match by name has the same layout. About 500 of DiIiS's opcode names
(many of them generic `SimpleMessage`/`IntDataMessage` slots) have no counterpart among the client's type names,
so they weren't compared.

### Attributes

| Difference | Status |
|---|---|
| Bounded integer attributes are packed by range; attribute 211 is a 32-bit float; 1482 is one bit. | Fixed |
| Eight attributes (resource types, pet owner/creator/type, conversation icons, primary damage attribute) store raw values. | Fixed |
| Five attributes are new: 490, 1065, 1476 (fourth Kanai's Cube slot), 1477 (ethereal items), 1484 (paragon cap). | Not needed yet |
| `Fiil1`/`Fiil2` (1223, 1224) can't be decoded by 2.8.0. | Safe: the server never sets them. |

### Game data

| Data | Difference | Status |
|---|---|---|
| GameBalance, items | A new 4-byte field at offset 280 moves item level through labels by 4; the padding field is gone; the record is 1408 bytes. | Fixed |
| GameBalance, paragon bonuses | A second block of 4 attribute specifiers (96 bytes) at offset 368. | Fixed |
| GameBalance, other tables | Same layout. | — |
| Globals | 8 bytes inserted at offset 684. | Not used by the server |
| Actor, Monster, Power | Same layout; only the header's format version and some balance values changed. | — |
| Everything else sampled | Byte-identical: Accolade, Act, Adventure, AmbientSound, AnimSet, BossEncounter, Condition, Conversation, EffectGroup, Encounter, LevelArea, Lore, Music, Observer, QuestRange, Recipe, Rope, Scene, SceneGroup, SkillKit, Tutorial, Weather, Worlds. Anim, MarkerSet, PhysMesh and Quest have a few edited files. | — |
| Followers | 2.8.0 uses new skill kits: Scoundrel_V2 (484937), Enchantress_V2 (484938), Templar_V2 (484941). | Open |

## Requests DiIiS ignores

These are messages the client sends that DiIiS has no handler for. They aren't 2.8.0 changes, but the features
won't work until they're implemented. Generated by `unhandled_msgs.py`; the list below leaves out console, PvP,
mail and party-vote messages.

| Opcode | Message | Feature |
|---|---|---|
| 113 | `AssignLegendaryPowerMessage` | Kanai's Cube powers |
| 531, 533, 535 | `PlayerLoadoutSaveMessage`, `PlayerLoadoutSetSlotMessage` | Armory |
| 542 | `SwapSkillsMessage` | Swapping skill slots |
| 26 | `StackPortionMessage` | Splitting a stack |
| 459 | `ItemJunkFlagChangedMessage` | Marking items as junk |
| 462 | `ParagonPurchaseResetCategory` | Resetting one paragon category |
| 374 | `UseIdentifyAllItemMessagge` | Identify all |
| 89 | `CancelLoopingSkillMessage` | Stopping a looping skill |
| 155, 472, 476 | `AcceptResurrectMessage`, `WarpDeadPlayerMessageg`, `TeleportToPlayerMessage` | Multiplayer |

A message with no class at all used to be worse than ignored: the server read its data as further messages. It now
logs a warning and drops the rest of that packet.

## Fixed during play testing

| Problem | Cause |
|---|---|
| Stuck on the loading screen | Item levels were read from the wrong offset, so a vendor had nothing to stock and world generation crashed. |
| Map crash going back to the local map | The last waypoint's level area was never sent (see above). |
| First waypoint click on the map did nothing | Teleporting from the map (`TeleportToWaypoint`, opcode 477) had no handler. |
| Projectiles hit after passing the target | Collisions were tested before moving, so each check covered the previous update's path. |
| Ray of Frost aimed into the ground | Monster paths ignored ground height, and the beam only turned on damage ticks. |
| General lag | Every client message cancelled any game update it overlapped, the console log table grew and redrew forever, and a misused attribute was logged thousands of times with source lookups. |
| A world froze for an update on entering some level areas | A level area marked for lazy monster loading had no scenes to load, and the lookup threw. |
| Kills of a bounty's unique in an override level area | No scenes matched the bounty's own level area there, so the kill handling threw before finishing. |
| Breaking a container could throw | A skill handled on the network thread raced a game update that had already destroyed it. |
| Crafting made one item and took the wrong materials | The handler for crafting several at once (370, which the 2.8.0 client sends) made one item whatever the count, knew only 3 of the currency-tab materials, and took gems before checking the rest. Crafting one item (369) had no handler. |
| Artisan workshops always looked like level 1 | The server never told the client which look to give the workshop next to each artisan (`Blacksmith_Crafting_Backbone` and the Jeweler and Mystic ones). Training also played the wrong animations from level 10 up. |
| Training an artisan to level 11 needed an extra Death's Breath | The check wanted more than the recipe's count instead of at least that many. |
| Gambling with Kadala did nothing | Nothing handled the gamble request (495). Kadala also read the blood shards saved when the world loaded, so shards picked up since didn't count, and her stock had no phylactery. |
| Level-70 magic and rare items had level 60 to 65 bases (Zischagge, Archon Crown), with less armor or damage than live's | DiIiS took any base from level 60 up for a level-70 item. Every equipment type has a level-70 base, and level-70 items now use only those, as on live. |
| Magic and rare items could drop or be gambled unidentified | DiIiS made 5% of them unidentified, and only 30% of legendaries. Since patch 2.0.1 live's magic and rare items are always identified, and every legendary and set item drops unidentified. `UnidentifiedDropChances` in `config.mods.json` now defaults to that (100 and 0), and goes by the quality the item rolled rather than its name. |
| Gambles and drops could be cosmetic rewards with no stats (Conqueror's Shako, Helm of the Hierarch) | DiIiS kept reward items out of the magic and rare pool by name, which missed the Conqueror's season set and the Hierarch pieces: about one in seven level-70 helms a Wizard gambled was one. Item flag `0x800000` marks every cosmetic reward (season, promo and anniversary items, transmogs), and those no longer roll. |
| Kadala's mystery weapons were rarely legendary for some classes, and low-level legendaries stopped dropping | A mystery weapon picked a weapon type first, so a Wizard's two-handed gamble that landed on a bow or crossbow could never be legendary. As in maxroll's gamble calculator, a gambled legendary is now picked by drop weight from every legendary of the slot's types that drops for the class, and can be of the player's level or below, or of level 16 or below at any level. DiIiS scales a legendary by overwriting its level in the shared item data, so after one was rolled at level 70 it counted as level 70 from then on. The pool now checks the level from the game data. |
| A game mode prompt at every login | The What's New screen's "Select A Play Mode". The client saves its account settings (request 8) and options (17), and the server dropped both, sending fixed settings at login. Hero settings (9, 10) were dropped too. |
| Tutorials showed with tutorials turned off, and came back | The options above, and the list of seen tutorials was reset each time one was added. |
| Loot and projectiles inside the ground outdoors | The ground height lookup left out the scene's own height, and walking monsters are kept at that height. |
| No arc or sound when items drop | The drop message named the source by its global ID, which the client doesn't know. |
| No animation or sound when identifying | Identify cast without its power, and the item was replaced on the client instead of changing, so it didn't flash. The hero's channel animation is the identify power's own animation. |
| Kanai's Cube kept items and materials, or made a result for free | Only the cow portal was implemented; every other transmute reported a power extraction. Recipes now come from the TransmuteRecipes table, whose 2.8.0 ingredients are 20 bytes. |
| Legendaries and loot ignored class | Drops passed no class. Loot now follows live's Smart Loot (85% for the player's class, with that class's main stat), and the drop table below says which legendaries drop for which class. |
| The legendary pool was far from live's: no Firebird's, Raekor's, Marauder's, Inna's, Akkhan's or Necromancer set pieces, no Nilfur's Boast, but crafted sets and old versions | DiIiS chose legendaries by name (retiring any not ending in `_x1`, leaving out set items and names without "unique") and a list of items it called bugged. Each item record holds the game's drop table (`Massive0`, at offset 964): a weight, 0 for items that don't drop at random, then a flag for each class (Demon Hunter, Barbarian, Wizard, Witch Doctor, Monk, Crusader, Necromancer). Drops, gambling and the cube now pick from it by weight, as live does. It matches maxroll's drop data for all but one item, where the installed game is a patch newer. Items with flag `0x40000` (Ancestors' Grace) drop only for hardcore heroes. Items with flag `0x4000000` (soul shards, ethereals, Hellforge Embers, Angelic Crucibles, and nothing else) are season theme items, and don't drop: the server runs no season themes. Every Wizard legendary can come from upgrading some rare type. Upgrading a rare of a type no legendary drops for your class (a crossbow for a Wizard) rolls for a class that can use it and one drops for, as live always upgrades; which class live rolls for isn't known. |
| Legendaries had no fixed stats (no Intelligence on Nilfur's Boast), too many secondary stats, and other classes' skill bonuses | DiIiS looked fixed affixes up in a list built from a field (`I0`) that is 0 for every affix in the game data, so it was empty, and gave legendaries the total of their random affix counts plus 3, from primary and secondary alike. It took an item's class for affixes from the last class its type allows (Monk, for boots), and rolled every tier at or above the item's level. Legendaries now get their fixed affixes, then their record's random primary (`BonusMajorAffixes`) and secondary (`BonusMinorAffixes`) ones; `AffixGroup` (1) marks secondary affixes. An affix rolls for the class the item is made for, using its class and its flag for each class; the tier is the one covering the item's level; and affixes are chosen by `Frequency`. Cooldown reduction and area damage roll again (DiIiS had them as "not in game"). |
| A transmute that matched no recipe animated and did nothing | The server answered with an empty result. A failed transmute is `TransumteFailedMessage` (361), whose value is a code from the client's table of errors (162 "Missing core ingredients.", 164 "Transmute failed.", 161 unidentified items, 160 socketed gems, 173 sets of fewer than 3 pieces); the client shows it and resets the cube. |
| Kanai's Cube couldn't upgrade rare helms, chests or belts | Their rares are of "Generic" item types that no legendary has; the legendaries are of the parent type. |

The server now logs how long its updates take every 30 seconds ("Updates in the last 30s: ...") at Debug level.

## Still open

- Followers' 2.8.0 skill kits.
- The server doesn't check that a crafting recipe has been learned; only the client's greyed-out button stops it.
- DiIiS takes legendary base stats from its own table (`UniqueItems.UniqueItemStats`), which lacks many current
  items. Those missing now take their base item's armor, as the table does. Its weapon damage matches the base item's
  for only 170 of its 301 weapons, so a missing weapon takes the stats of an older version of itself (same actor and
  type). The 21 ethereal weapons have no older version, so they'd need stats before a season theme could drop them.
- Season themes (soul shards, ethereals and the rest) aren't implemented; their items never drop.
- Six legendaries DiIiS listed as bugged, without saying why, now drop because live drops them: Akarat's Awakening,
  Dishonored Legacy, Guard of Johanna, Vo'Toyias Spiker, SuWong Diviner and Blood Brother. Not tested yet.
- Kanai's Cube: extracting and equipping legendary powers, Remove Level Requirement, Convert Gems, Augment, Primalize,
  the Greed portals and Blackrock Ledger aren't implemented. DiIiS implements only about a dozen legendary powers.
- Below level 70, normal, magic and rare items take a base within 3 levels of the item's (DiIiS's rule); live's rule
  there isn't known.
- Kadala's split between magic and rare items isn't known; it's even for now.
- Magic and rare items still roll their affix count from primary and secondary affixes together; live's split for
  them isn't known yet.
- An `unescaped ']'` markup exception when level areas load.
- The game server listens on 2001 but registers itself as 1345, and `GetWebSocketLocation` hard-codes 192.168.1.100.
- Monsters set `Hitpoints_Max_Total`, a calculated attribute, directly (now logged once).
- Adventure-mode act values in `GameSyncedData` are inconsistent (-1, 0 and 1 in different places).
- Teleporting from the map is instant; the real game has a short cast bar.
- `SQLitePCLRaw.lib.e_sqlite3` 2.1.2 (from Entity Framework Core 7, used for the MPQ data mirror) has a known
  vulnerability; it only opens local files.

## Runtime

The server targets .NET 10 (.NET 8 support ends on 10 November 2026). Moving past .NET 8 needed NHibernate 5.5.2
or later, because older versions reject every entity on .NET 9+ (nhibernate-core#3536); it now uses 5.5.4, which
also fixes a SQL injection advisory. Npgsql moved from 7.0.1 to 7.0.10 for the same reason. DotNetty 0.7.6's TLS
works on .NET 10; 0.7.5 hung on .NET 8.
